# 组会 PPT 生成提示词（ECDot-S / RK3588 部署）

## 用法

1. 复制下面「提示词正文」整块，粘贴给能直接出稿的 PPT 模型/工具（Kimi PPT、Gamma、WPS AI、讯飞智文等）。
2. 若对方不能读本地文件，**不要删事实清单**，它已经把所有数字内嵌了。
3. 生成后按文末「验收清单」逐条核对；不合格就把对应那条要求单独再发一次。

## 提示词正文（从下一行开始复制）

你是资深技术汇报设计师，同时具备 CV 部署工程背景。请为一次 **10–12 分钟的研究生组会** 制作一套 **12 页** 的中文 PPT，主题是「ECDet-S 轻量检测模型在 RK3588 上的 INT8 量化部署」。听众是同实验室的老师和同学：懂深度学习，但大概率不懂瑞芯微 NPU 的部署细节。

### 一、硬性约束（优先级最高，冲突时以此为准）

1. **页数必须正好 12 页**，不多不少。第 1 页是封面，第 12 页是 Q&A/备份页。
2. 画布 **16:9，13.333 × 7.5 英寸**。
3. **字号下限（不许为了塞内容而缩小）**：
   - 封面主标题 **40–44 pt**，页面标题 **36–40 pt**
   - 正文/要点 **28–32 pt**
   - 表格正文 **20–22 pt**，表头 **22 pt**
   - 注释/来源 **16–18 pt**（仅用于页脚一行小字）
   - 任何一页出现 < 20 pt 的正文都算不合格。
4. **每页只讲一个结论**：页面标题直接写成一句结论（例如「INT8 比 FP32 只掉 0.11 个点」），不要写「实验结果」这种空标题。
5. **每页要点 ≤ 5 条，每条 ≤ 22 个汉字**；宁可留白，不要堆满。
6. **内容溢出时的处理顺序**：先删要点 → 再把细节移到演讲者备注 → 最后才允许拆页（但总页数不能变，所以优先删）。
7. 视觉：白/浅灰底 + 深色字，**关键数字用强调色放大到 40–54 pt 单独占一块**；全篇最多 2 个强调色；不要装饰性图片、不要渐变、不要阴影、不要 3D。
8. 数字一律用**表格或大字号数字卡片**呈现，不要写成一段话。
9. 中文字体优先「思源黑体 / Microsoft YaHei / Noto Sans SC」，英文与数字用 Arial 或 Helvetica。
10. 每页配 **80–140 字的演讲者备注**（口语化，不是复述页面文字）。

### 二、事实清单（唯一数据来源，禁止改动、禁止补充）

- 模型：ECDot-S（D-FINE 变体：ViTAdapter + HybridEncoder + ECTransformer），VisDrone 10 类检测，300 个 query。
- 输入：**1×3×640×640，static，uint8 RGB NCHW，0..255**。
- 流水线：PyTorch → ONNX（opset 17）→ 300 张校准 → RKNN w8a8 + FP16 hybrid → RK3588；一条命令 `TRAIN_ENV=default RKNN_ENV=rknn ./deploy/run_all.sh` 全流程可复现。
- 预处理：**直接 stretch 到 640×640，PIL bilinear**；无 letterbox、无 pad、无 /255、Python 里不做 mean/std。
  - 用 cv2 `INTER_AREA` 替代：FP32 从 28.82 掉到 28.65，INT8 掉约 0.25。
- 归一化烤进 `.rknn`：RGB mean `[123.675, 116.28, 103.53]`，std `[58.395, 57.12, 57.375]`，`quant_img_RGB2BGR=False`。
- 量化配置：`w8a8`、per-channel、`auto_hybrid=True`、`auto_hybrid_cos_thresh=0.9999`（RKNN 默认 0.98；**这是余弦距离上界，越大 = 越多 FP16 回退**）、保留 LQE、score-head clamp ±10 / ±30、final logits clamp ±30。
- 校准：VisDrone train 300 张，seed=42，按主类分层（D'Hondt 配额）；带**非有限值过滤**。
- 输出：`pred_logits [1,300,10]`（**sigmoid 之前**）+ `pred_boxes [1,300,4]`（归一化 cxcywh）。
- 后处理：sigmoid → 展平 3000 → top-300 → `label=idx%10`、`query=idx//10` → cxcywh→xyxy → x×orig_w、y×orig_h → clip → COCO xywh；**无 NMS**。
- 精度（VisDrone val 548 张，COCOeval）：

  | 指标 | PyTorch | FP32 ONNX | RKNN INT8 | 掉点 |
  |---|---:|---:|---:|---:|
  | AP | 28.82 | 28.8208 | **28.7075** | 0.1133 |
  | AP50 | 48.54 | 48.5410 | 48.5089 | 0.0321 |
  | AP75 | 28.63 | 28.6290 | 28.3918 | 0.2372 |
  | APs | 18.67 | 18.6712 | 18.5602 | 0.1111 |
  | APm | 41.47 | 41.4749 | 41.3606 | 0.1143 |
  | APl | 61.67 | 61.6736 | 61.4027 | 0.2708 |

- 验收门限：**单边**判定，`INT8_AP >= reference_AP − 1.0`（reference_AP = 同一次运行的 FP32 stretch 基线 28.8208）。当前 drop 0.1133，通过。单边的原因：INT8 偶然高于 FP32 是量化假象，不该算回归。
- 模型体积：49,837,410 B（约 48 MiB）。
- 运行环境：rknn-toolkit2 / toolkit-lite2 / librknnrt 均 **2.5.0**，Python 3.10/3.11，numpy<2；另有 C++17 参考实现（RKNPU2 C API）。
- 板端识别输出：**按元素个数，不按 index** —— 3000 = logits，1200 = boxes。
- 板端验证四步：① 预处理 tensor 逐字节对齐（须用非 640×640 原图，否则 resize 路径根本没被走到）→ ② 单图输出对齐 → ③ 50–100 张板端 mAP（≥ reference_AP − 1.0）→ ④ 延迟：warmup 20 次 + 测 100 次，再跑 30–60 分钟压测看降频。
- **仿真器 1.21 s/张不是板端延迟**，板端延迟目前尚未实测。

#### 严禁出现的表述

- 不得把归档版本的 **28.6887** 当作当前结果（那是历史构建记录，当前是 28.7075）。
- 不得出现任何**板端实测延迟 / FPS / 功耗 / 温度**数字——这些还没测，只能写「待实测」。
- 不得使用「大幅提升」「显著优于 SOTA」「完美部署」这类无依据的话。
- 不得声称做了 NMS、letterbox、或 Python 端归一化。

### 三、逐页大纲（严格按此结构，可微调措辞）

1. **封面**：主标题「ECDet-S 在 RK3588 上的 INT8 部署」；副标题「从 PyTorch 到板端：一份冻结的模型契约」；底部：汇报人【姓名】、日期【日期】、组会。
2. **先给结论**：三个大数字并排 —— `28.71 AP`（INT8）、`−0.11`（相对 FP32）、`48 MiB`（单模型体积）；一句话：「精度几乎无损，全流程一条命令可复现，现在缺的只是真机数据」。
3. **为什么这件事不简单**：边缘部署的四个坑 —— 预处理不一致、量化后分数塌陷、输出顺序不确定、离线仿真 ≠ 真机。每条一句，铺垫后面的内容。
4. **模型与流水线**：左侧模型信息（ECDot-S / VisDrone 10 类 / 300 query / 640×640 静态）；右侧五步流程箭头图（PyTorch → ONNX 17 → 校准 300 → RKNN w8a8 → 仿真评测）。
5. **预处理契约**：一张对比图/两栏 —— 左边「我们的做法：stretch + PIL bilinear」，右边「不要做的：letterbox / pad / /255 / cv2 替代」；底部一行红字：cv2 替代直接掉约 0.25 AP。
6. **归一化与量化**：说明 mean/std 在模型内部、板端喂 uint8 即可；三个关键旋钮：`w8a8 + per-channel`、`auto_hybrid 0.9999`、保留 LQE + clamp。用一句话解释 0.9999 是「余弦距离上界，越大越保守」。
7. **输出与后处理**：一条流程图：`[1,300,10]` 与 `[1,300,4]` → sigmoid → top-300 → `idx%10 / idx//10` → ×orig_w,orig_h → clip → COCO；右侧两个「为什么」小卡：为什么 TopK 放图外、为什么没有 NMS。
8. **精度结果**：放上表（可只保留 AP / AP50 / AP75 / APs / APm / APl 六行），**AP 那一行的 drop 0.1133 用强调色**；右下角小卡：门限是单边的 `drop ≤ 1.0`，为什么单边。
9. **踩过的坑（本页最重要）**：三行「症状 / 根因 / 修复」小表 ——
   ① 仿真 AP = 0.00 → 校准集混入 1 张让 gather 产生 +inf 的图，scale 变 inf → 过滤所有 decoder gather 的非有限值；
   ② 板端 AP 只有 28.4 → 用 cv2 resize 顶替 PIL → 换回 PIL 或做字节级对齐验证；
   ③ 检测框整体错位 → 还在用 letterbox 反变换 → 改成直接乘 orig_w/orig_h。
10. **板端运行时与验证**：左侧 Python（rknnlite）/ C++（RKNPU2）两条路径各一行关键代码要点（`want_float=1`、`pass_through=0`、**按 3000/1200 元素数认输出**）；右侧四步验证阶梯图。
11. **现状与下一步**：左栏「已完成」：契约冻结、INT8 精度达标、C++ 参考实现、可复现脚本；右栏「待做」：真机 mAP、端到端延迟分解、30–60 分钟热稳定、多核 core_mask 对比。底部一行风险：真机与仿真不一致时，先查预处理 tensor，不要先动量化和解码。
12. **Q&A / 备份页**：只放 5 条不可变更的 invariant（输入 640 uint8 RGB、stretch+PIL、mean/std 在图内、后处理无 NMS、输出按元素数识别）+「谢谢，欢迎提问」。

### 四、交付方式

- **直接出片**：由你自身直接生成并导出 `.pptx` 文件，文件名 `ECDot-S_RK3588_组会.pptx`。
- **禁止输出代码**：不要输出 python-pptx / VBA / LaTeX / HTML 之类的生成脚本，也不要说「你可以运行这段代码得到 PPT」。要的是成品，不是代码。
- **只给可编辑的文字与版式**：如果平台需要分步确认，先一次性给全 12 页的标题、要点、表格数据、备注和配色/字号说明，再让我点导出。
- **兜底**：只有当你确实无法导出 pptx 时，才输出等价的 Markdown 大纲，每页格式为 `## 第 N 页 | 标题` + 要点 + `> 备注：...`，并附字号与配色建议。
- 生成后请**自检并明确回复**：实际页数、全篇最小字号、是否有任何数字不在事实清单中、是否有页面要点超过 5 条。若有不满足的，自行修正后再交付。

### 五、语气

讲人话。少用「本文提出」「综上所述」，多用「我们发现」「这里踩了个坑」。允许在备注里写一句自嘲或对比（例如「仿真跑 1.2 秒一张，别拿这个当板端延迟」）。
